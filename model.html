鱼缸壁面清洁机器人 — 整机三维示意

three.js 按文档尺寸 1:1 建模 · 结构 / 步态 / 过棱 / 回坞四个模式 · 每一帧的腿长与膝角都是逆解算出来的

结论先行：这一版能看什么，看出了什么

一、四个模式，同一个模型。 「结构」是静态装配，可以分层展开、透视主腔； 「步态」让三足 3-RPR 真的走起来，刷辊在玻璃上擦出一条干净的带子； 「过棱」演示 90° 直角棱的三步换面；「回坞」演示精定位、作业头退让和感应充电。 三个动画里的腿都不是摆出来的：每一帧由机身位姿和吸盘落点逆解出伸缩段 l1 与膝角， 读数面板实时显示，越限就变红。

二、布局已经跟到最新基准。 腿 a / b / c 与铰点座 (43.3, −25) / (0, +50) / (−43.3, −25)、刷辊站在 y = +18、 铰点座 b 靠跨梁吊在机尾、前窗模块和坞站圆盘偏心到 (−15, −32) —— 上一版模型的坐标系还是反的， 刷辊画在机头，这些都已重做。

三、建模暴露了四件事，列在 第 8 节。 最硬的一条：前窗罩压住了铰点座 c（中心距 29.2 mm，罩半径就有 26.5）； 其次，跨梁只能走 z = 56–64 这 8 mm，否则作业头退让 20 mm 时刷辊会顶上去； 伸缩段下限若就是 50.4 mm，平贴步距只能到 14.5 mm； 过棱三步在连续性上是走得通的，行程不用加，但膝要折到 85°，而不是表里的 78°。

打开方式：双击即可。three.js 从 CDN 取，第一次打开需要联网；离线会看到一段说明，正文照常可读。

2建模约定与数据来源

三维模型的坑几乎全部来自「口径没说清楚」：哪个方向是 y、厚度从哪算起、这个数是谁给的。 这一节先把口径钉死。

A坐标系：跟着运动单元第 1 节走

轴定义为什么这么定
+x机身右侧（从缸内看向玻璃） 与 motion.html 第 1 节的铰点表同一口径
+y指向机尾。机头（前足 A）在 y = −100，行进方向是 −y 同上。三份文档里的 (43.3, −25)、y = +18、(−15, −32) 可以原样抄进 CFG
z离玻璃内表面的距离，0 = 玻璃面 与 body.html 第 1 节的 0–18 / 18–30 / 30–58 / 58–64 同一口径
单位1 个 three.js 单位 = 1 mm参数表里的数原样用，不换算
这套 (x, y, z) 是左手系 —— 模型里只在一个函数里处理它
x 向右、y 向机尾、z 离开玻璃，三者构成左手系。three.js 是右手系、y 朝上， 所以代码里的约定是：文档坐标只出现在 CFG 和零件函数里， 进场景之前一律过 L(x, y, z) = (x, −y, z)。 于是「步态」和「结构」里机头朝上、爬升方向就是屏幕上方；「过棱」把整机转 90°，机头指向缸角。

B文档值、推导值、示意值

CFG 里每个数右边都标了来源，只有三类。带 // 示意 的数不能当设计输入， 定稿要写回对应文档。

标注含义能不能改
// src: 文档 §N文档正文或表格里明确给出的数 改它等于改设计，必须回头同步那篇文档
// 推导由文档值算出来的（L₀ = 86.603、轴心 z = 17、过棱关键帧…） 不要手改，改上游让它重算
// 示意文档没给、为了让模型能看而取的 随便改，但它一旦被引用，就成了事实上的设计
这一版里最要当心的六个示意值
① 腿的杆径与级数。文档只给「两级伸缩、杆径 ∅8–10」。模型画外管 ∅10 / 中间级 ∅8 / 末级 ∅6，膝铰座 ∅14。
② 跨梁的截面。文档只说「从刷辊上方跨过去」。模型取 12 × 8 mm、z = 56–64 —— 这个高度不是随手取的，是作业头退让逼出来的，见 第 8 节 ②。
③ 刷辊的驱动仓。文档给了磁耦合 ∅30 / 4 极 / 1.2 mm 气隙，没给仓体。模型放在 +x 端（右侧在 y = +1 处没有杆）。
④ 作业头的机架与刮条。刮条几何文档明确未给，只有 Shore A 40 和「y ≈ +38 ~ +42」。
⑤ 主腔内部件的摆位。文档只给质量和「电机全部横放」。
⑥ 吸附电机的位置。模型把 ∅12 × 24 空心杯横放在吸盘单元的 18–30 层里，贴着踝环。

3结构与布局

三足布局是这台机器上唯一「一个数字定死一片」的地方：R_t、r、错开角三个数一定， 铰点座、腿、刷辊的站位就全定了。切到「结构」模式、「正视」视角对照着看。

A三足与腿 a / b / c

腿吸盘（脚）机身铰点座座怎么挂在机身上
aA · 前足 (0, −100)330° · (43.3, −25)主腔底面的凸台，向下伸到传动层
bB · 机尾右 (86.6, +50)90° · (0, +50)跨梁吊在机尾，从刷辊上方过去再下探到 z = 18
cC · 机尾左 (−86.6, +50)210° · (−43.3, −25)主腔底面的凸台（与前窗罩相撞，见第 8 节 ①）
腿的中位长只由两个圆决定，三条相等
L₀ = √(100² + 50² − 2·100·50·cos 60°) = √7500 = 86.603 mm， 拆成伸缩段 l1 = 56.6 + 膝到踝定长 l2 = 30（motion.html 第 11 节 C）。
每条腿的关节链：方位铰（被动）→ 俯仰（主动）→ 两级伸缩（主动）→ 膝（被动弹簧 + 锁止）→ 远端段 → 踝环。 平贴时膝角 0，外形和一根直杆没有区别；膝只在过棱时折起来。
自检表第一行还会实算一次雅可比行列式，确认 60° 错开非奇异、0° 径向布置恒为 0。

B机尾：刷辊、刮条与跨梁

主腔占 y = −85 ~ 0，机尾那一截全让给作业头：刷辊 y = +1 ~ +35，刮条 y ≈ +38 ~ +41， 杆 b 压在 y = +50。三样东西之间都只剩几毫米。

  • 刷辊 ∅34 × 80，轴心 (y, z) = (+18, 17)。 ∅34 按外径取（芯 ∅18 + 刷丝 8 mm），丝尖正好触玻璃。 文档另写了「占 z = 8–42、z_b = 25」—— 那是按 ∅34 是芯算的，两种说法只能取一，见第 8 节 ⑤。
  • 作业头整体装在一对 z 向滑槽上，可被动退让 20 mm（对接时让出前窗模块的位置）。 模型里刷辊、刮条、端板一起走这 20 mm。
  • 跨梁从主腔尾面伸出，经刷辊上方到 y = +50 再下探，末端就是铰点座 b。 它和刷辊之间的余量决定了作业头能退多少。
  • 磁耦合驱动仓放在 +x 端。−x 端是杆 c 的走廊（y = +1 处杆 c 只在 x = −58.3），放不下。

C前窗模块与坞站偏心

前窗模块是一个从主腔底面（z = 30）伸到离玻璃 2 mm 的 POM 罩，里面装 Ø50 接收线圈、天线和 4 个光电管。 它的中心按 dock.html 第 1 节放在 (−15, −32)，坞站的 Ø90 圆盘跟着它一起偏心。

三维里一眼就能看到的问题：罩体啃进了铰点座 c
罩心 (−15, −32) 到铰点 c (−43.3, −25) 只有 29.2 mm，而罩体半径光线圈加壁厚就要 50/2 + 1.5 = 26.5 mm，剩 2.7 mm 装一个 ∅14 的铰点座 —— 装不下，重叠约 4.3 mm。 dock.html 第 1 节查过「盘边离铰点 a 13.7 mm」，但没有查罩体离铰点 c。
透视主腔打开，在「正视」视角里能直接看到。候选修法见 第 8 节 ①。

5步态动画

「步态」模式在一块长了藻的前玻璃上连走 5 个循环。默认「缸外」视角 —— 就是站在鱼缸前看它干活的样子。

A一个循环四拍

拍n发生什么刷辊
① 工作相3三杯不动，三根腿协同伸缩，机身前移 d = 12 mm转
② 换步 A2前足松开 → 俯仰轴把杯抬起 5 mm → 前移 12 mm → 落下吸附停
③ 换步 C2机尾左，同上停
④ 换步 B2机尾右，同上停

机身在每个循环里从三角形中位后 6 mm 走到中位前 6 mm，这样三条腿的伸缩对称地分在中位两侧。 n = 2 时刷辊停转是 work.html 第 7 节 ④ 的硬互锁； 抬杯用的是过棱新加的俯仰轴，平贴步态顺带也用上了。

B平贴步距被伸缩段下限卡住

d = 23 mm 那档要 l1 = 46.9 mm，低于过棱表的 50.4
机身前移时杆 a 缩短得最多：中位前 d/2 处， l1 = √(43.3² + (75 − d/2)²) − 30。 d = 12 → 51.5 mm（动画里的值，在 50.4 → 105.9 内）； d = 23 → 46.9 mm（出界 3.5 mm）。反推 l1 ≥ 50.4 允许的最大步距是 14.5 mm。
所以「伸缩段要覆盖 50.4 → 105.9」只是过棱的需求，平贴步态要的是更短的那一头。 两条路：伸缩杆规格下限按 46.9 选（对两级管不难，收拢长度多让 3.5 mm）， 或者把平贴步距限在 ≈ 14 mm（与第 7 节横向偏移 ±10 mm 那档本来就接近）。
这里的 l1 是把机身在中位两侧对称走算出来的；偏航和横移会让某一条腿更短，真实下限只会更低。

6过棱换面动画

「过棱」模式把机器人放到前玻璃与侧玻璃的 90° 内角前，机头指向缸角。 整段动画的姿态是本页离线搜出来的，搜索判据就是 motion.html 第 11 节的那几条， 加上它没来得及做的「步与步之间连续」。

A腿的解法与步序

  • 每条腿的逆解：踝在杯心正上方 24 mm；膝落在以踝为心、半径 30、平行于该杯所在玻璃面的圆上 （远端段始终贴着玻璃，第 11 节 C）。在这个圆上挑一个点，使 l1 在 50.4 → 105.9 内、膝角 ≤ 85°、 杆件不穿进主腔，并让 l1 尽量留在机身平面里（「近端段两端同高」）。
  • 步序 C → B → A。先把机尾左杯直接甩到侧玻璃（它的铰点座在机身前左，够得着）， 机身抬头转到约 59° 再挪机尾右杯，最后机身贴平到侧玻璃上、把鼻杯送到 h1 + 150 = 180 mm。
  • 落点与文档一致：两只尾杯落在侧玻璃 h1 = 30 mm、鼻杯 180 mm；起点机身离棱 130 mm（下限 115.5）。
  • 和文档不一样的一点：第 11 节 D 说「瓶颈永远是步 1 —— 尾右杯」。 本页先走的是尾左杯：铰点圆转了 60° 之后左右不对称，座 c 在机身前左、座 b 在正后方， 尾左杯离棱更近的铰点够得着。第 11 节的中间姿态没有公开，两边步序是否等价没法对照。

B连续性补上之后的读数

量文档（第 11 节 D，θ = 90°）本页（整段动画逐帧）
伸缩段 l150.4 → 105.9 mm—
膝折角≤ 78.0°（「膝要能折到 85°」）—

第 11 节 E ① 担心「步与步之间的连续性没有检查，真实需要的行程会比上表略大」。 按本页的腿模型，连续的三步路径在同一个 50.4 → 105.9 里就走得通， 代价落在膝上 —— 机身从贴平转到约 60° 的那一段，三条腿的膝同时折到 80–85°。 这正好压在文档自己定的「膝要能折到 85°」上限，锁止机构和角度传感器的量程要按 85° 选，不是 78°。
摆动腿（悬空那一条）在关节空间里插值，再沿「角平分线 + 朝髋收腿」抬起 20 mm 绕过缸角； 它的 l1 与杯心离玻璃的净距也在自检表里逐帧查了。这条轨迹是本页选的，不是文档给的。

9怎么改这个模型

写给后面来接手的 Agent。模型的全部可调量在一个对象里，改尺寸不需要读渲染代码。

  • ① 改尺寸 → 只动 CFG。按「玻璃与坞站 → 三足 → 腿 → 厚度 → 主腔 → 作业头 → 前窗 → 动画」分组， 每条都有 // src / // 推导 / // 示意。
  • ② 改形状 → 只动对应的 build*()。 buildGlass / buildCorner / buildAlgae / buildDock / buildFoot / buildLeg / buildSeats / buildBeam / buildCavity / buildCover / buildShroud / buildHead / buildPod / buildInternals / buildField， 一个函数一个零件，互不调用，各自返回一个 Group。腿和脚每帧由 poseLeg / poseFoot 摆位。
  • ③ 加了新零件 → 在 LAYERS 里登记。不登记的组不会跟着「分层展开」走。
  • ④ 标注自动排布，不用手调坐标。buildLabels() 只写「锚点（文档坐标）+ 文字」， 排布按锚点的屏幕位置分左右两栏、逐条避让。改完跑 BOT.labelLayout() 看有没有出框或压住。
  • ⑤ 动画 = 时间线函数。gaitTimeline / crossTimeline / dockTimeline 各返回 { T, at(t) }，at 只给机身位姿、杯位和几个开关量，腿全由 legIK 现算。 过棱关键帧在 CFG.cross.keys，改了之后自检表会重新逐帧检查。
  • ⑥ 约束写进 checks()。它会渲染成第 3 节 D 的表并 console.table， 不通过的行在页面上标红，「待选型」类标成普通行加 ⚠。
  • ⑦ 不要在 HTML 里写 <style>。叠加层、读数面板、标注的外观类全在 assets/notion.css 的「3D 视图」段里。
