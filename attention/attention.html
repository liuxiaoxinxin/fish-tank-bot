读懂 Attention Is All You Need

给程序员的 Transformer 论文交互式精读 · Vaswani 等 · NeurIPS 2017 · arXiv 1706.03762

点任意一个词，看它在“注意”谁。再换掉句尾那个词：

紫色越深，表示被选中的词（蓝框）分给这个词的注意力越多。权重为演示手工设定，用来说明真实模型里观察到的现象。

结论先行：整篇论文的一句话版本

把句子里每个词都变成三个向量：Query、Key、Value。每个词拿自己的 Query 去和所有词的 Key 比相似度，按相似度把所有词的 Value 加权平均，结果就是这个词的新表示。把这件事并排做 8 份（多头），再叠 6 层，就是 Transformer。

这篇 15 页的论文是 GPT、BERT 和今天大语言模型的起点。下面 11 节按论文顺序讲，每节都有一个能动手的实验。你只需要会写代码，记得矩阵乘法是什么。

1RNN 为什么不够好§1 · §4 · 表 1

论文要解决的问题：串行计算太慢，远处的词互相够不着。

2017 年以前，机器翻译的主力是 RNN（LSTM、GRU）。RNN 的工作方式像一个 for 循环：读完第 1 个词才能读第 2 个，第 t 步的状态依赖第 t−1 步。

这带来两个问题。第一是慢：GPU 有几千个核，RNN 却只能一个词一个词串着算，句子越长越吃亏。第二是远处的词很难互相影响：第 1 个词的信息要经过 n−1 次传递才能到达第 n 个词，一路上被逐渐冲淡。

# RNN：天然串行，第 t 步必须等第 t-1 步算完
h = h0
for x in xs:
    h = f(h, x)

# 自注意力：一次矩阵运算，所有位置同时算
out = softmax(Q @ K.T / sqrt(d_k)) @ V
10

上：RNN 每个时钟周期只能处理一个词，第一个词到最后一个词要走 n−1 步。下：自注意力一步算完，任意两个词之间都有直接连线（紫线）。

层类型每层计算量串行操作数任意两词的最长路径
Self-AttentionO(n²·d)O(1)O(1)
Recurrent（RNN）O(n·d²)O(n)O(n)
Convolutional（CNN）O(k·n·d²)O(1)O(logk n)

论文表 1 的读法：n 是句子长度，d 是向量维度（512），k 是卷积核宽度。翻译的句子通常远短于 512 个词，所以自注意力的 n²·d 反而比 RNN 的 n·d² 更省；串行步数和最长路径都从 O(n) 降到 O(1)。论文的主张因此写在标题里：把循环整个扔掉，只用注意力。

2注意力是一次模糊的字典查询§3.2

用程序员熟悉的 dict 理解 query、key、value。

论文对注意力的定义只有一句：把一个 query 和一组 key-value 对映射成一个输出；输出是所有 value 的加权和，每个 value 的权重由 query 和对应 key 的相似度决定。

这就是字典查询，只是变模糊了。普通字典要求 key 完全相等，命中一个就返回一个。注意力拿 query 跟每一个 key 都算一个相似度，再把所有 value 按相似度加权平均。

# 普通字典：key 必须完全相等，只返回一个 value
d = {"猫": v_cat, "狗": v_dog, "汽车": v_car}
d["猫"]

# 注意力：和每个 key 算相似度，返回所有 value 的加权平均
w = softmax([q @ k for k in keys])     # 权重加起来等于 1
out = sum(w[i] * values[i] for i in range(len(keys)))
拖动蓝色的 query 箭头（也可以点选后用方向键） 1.0×
KEYq·k权重

每个 key 是一个二维向量（橙色箭头），它对应的 value 是一种颜色。相似度用点积 q·k：方向越一致、箭头越长，分数越高。softmax 把分数变成加起来为 1 的权重，输出就是按权重混合出来的颜色。数字由页面实时计算。

试着把 query 拖远一点：方向不变，长度变长，分数整体变大，权重会越来越集中到一个 key 上。记住这个现象，第 4 节会用到。

自注意力里，每个词同时扮演三个角色：用 Q 去问别人，用 K 回应别人的询问，用 V 提供自己的内容。三者都是同一个词向量分别乘以三个矩阵 WQ、WK、WV 得到的，这三个矩阵是训练学出来的。

3把公式一步步算出来§3.2.1 · 公式 (1)

全文最重要的一行，用 4 个词的句子手算一遍。

下面这个句子的词向量是 4 维，dk = 3，数字全部由页面实时计算。点“下一步”往前走，鼠标停在结果矩阵的格子上，看它是怎么来的。

Attention(Q, K, V) = softmax(QKT√dk) V







  
回头看这个过程：softmax 是按行做的，每一行是一个词分配给所有词的注意力；整个计算只有矩阵乘法和一次 softmax，没有任何循环，所以 GPU 能一口气算完整个句子。第 1 节说的“一步到位”指的就是这件事。

  
论文也比较了“加性注意力”（用一个小网络算相似度）。两者理论复杂度差不多，但点积能直接用高度优化的矩阵乘法，实际更快、更省内存。










4为什么要除以 √dₖ§3.2.1 · 脚注 4


公式里唯一看起来奇怪的地方。



论文在脚注里给了解释：假设 q 和 k 的每个分量都是均值 0、方差 1 的独立随机数，那么点积 q·k 的方差就是 dk。维度是 64 的时候，分数的标准差就是 8。


分数之间差距一大，softmax 就会把几乎全部权重给最大的那个，其余接近 0。




  

    64
    
    
  

  

  

  

  
1 个 query 和 8 个 key，每个分量从标准正态分布随机抽取，数字由页面实时计算。先不勾选，把 dk 往右拖；再勾上对比。






  
不缩放的后果：softmax 饱和后梯度趋近 0，除了得分最高的那个 key，其他 key 的参数几乎收不到更新，模型学不动。对策就是除以 √dk，把分数的方差拉回 1。论文用 dk = 64，所以实际是除以 8，“Scaled Dot-Product Attention”里的 Scaled 指的就是它。










5多头注意力：同时用几种方式看句子§3.2.2 · 附录图 3–5


一次注意力只能学到一种关注方式，所以并排做 8 份。



一个词和其他词的关系有很多种：它指代谁，它修饰谁，它前面是谁。论文把 512 维拆成 8 份，每份 64 维，各自独立做一次注意力，最后再拼回 512 维。每一份叫一个“头”（head）。




  

  

    
    

      

      

    

  

  
每一行是一个词（左侧）分给所有词（上方）的注意力，紫色越深权重越大。点任意一行查看。句子取自论文附录图 4；4 个头的权重为演示手工设定，模仿论文附录图里真实观察到的模式。





MultiHead(Q, K, V) = Concat(head1, …, head8) WO，  headi = Attention(QWiQ, KWiK, VWiV)


# x: (n, 512)
heads = []
for i in range(8):                          # 真实实现是一次 reshape，没有循环
    q, k, v = x @ Wq[i], x @ Wk[i], x @ Wv[i]   # 各 (n, 64)
    heads.append(attention(q, k, v))        # (n, 64)
out = concat(heads, axis=-1) @ Wo           # (n, 512) @ (512, 512) → (n, 512)




  
8 个头几乎是白送的：每个头只有 64 维，8 个头加起来的计算量和一个 512 维的单头差不多。论文表 3 的消融实验：只用 1 个头，BLEU 从 25.8 掉到 24.9；头太多也不好，32 个头掉到 25.4。










6位置编码：告诉注意力词的顺序§3.5


注意力天生不看顺序，要另外把位置“加”进去。



把句子打乱，自注意力给每个词算出来的结果完全一样，只是换了个位置。下面这个小实验是真算的：同一个自注意力，分别处理“狗咬人”和“人咬狗”，比较“狗”这个词的输出。




  

  

  
词向量 4 维，Q = K = V = 词向量（省略了投影矩阵），数字由页面实时计算。





没有位置编码时，自注意力看到的是一个“词袋”，狗咬人和人咬狗对它来说没有区别。论文的办法是给每个位置一个固定向量，直接加到词向量上（不是拼接）：


PE(pos, 2i) = sin(pos / 100002i/dmodel)    PE(pos, 2i+1) = cos(pos / 100002i/dmodel)


可以把它想成二进制计数器的连续版本。数 0000、0001、0010、0011……最低位每一步都翻转，越高的位翻得越慢。位置编码也一样：低维度波长短、变化快，高维度波长长、变化慢，组合起来每个位置都有独一无二的“指纹”。

纵轴是位置 0–49，横轴是维度。橙色为正，蓝色为负。左边几列条纹密（变化快），越往右条纹越宽（变化慢）。






  
为什么选正弦而不是学一张表：论文两种都试了，效果几乎一样（表 3 第 E 行：25.7 对 25.8）。正弦版有可能外推到比训练时更长的句子，而且任意固定偏移 k 的 PEpos+k 都能写成 PEpos 的线性函数，方便模型学习“相对位置”。

8遮罩与逐词生成§3.1 · §3.2.3


训练时整句并行但不许偷看，推理时只能一个词一个词写。



A因果遮罩：训练时不许偷看


解码器生成译文时，第 3 个词还没写出来，第 2 个位置当然不能看它。但训练时为了并行，整句译文是一次性喂进去的，所以要人为挡住“未来”：在 softmax 之前把右上三角的分数设成 −∞。e−∞ = 0，这些位置的权重就变成 0。




  
点任意一行

  

  

  
解码器输入是右移一位的译文：开头补一个起始符 <s>，第 i 个位置负责预测第 i+1 个词。分数为示意的随机数，softmax 由页面实时计算。





B推理：一个词一个词写


推理时没有正确答案可抄，只能逐词生成：每生成一个词，就把它接到解码器输入后面，再跑一遍。编码器只需要跑一次，它的输出会在每一步被交叉注意力反复查阅。




  

    
    
  

  

    
编码器输入（英文原句，只算一次）· 紫色深浅 = 当前这一步的交叉注意力

    
解码器输入（已经写出的德语）

    
下一个词的概率（前 3 名）

  

  

  
概率与交叉注意力权重为示意。这里每步取概率最高的词（贪心）；论文实际使用束搜索，beam size = 4，长度惩罚 α = 0.6。






  
关掉遮罩会怎样：训练时每个位置都能看到答案，损失会降得很漂亮；推理时后面的词根本不存在，模型从没学过“只看左边”该怎么预测，生成结果直接崩掉。对策：解码器的自注意力必须带遮罩，编码器的自注意力和交叉注意力不需要。

10它为什么改变了一切


能并行、结构通用，拆开一半也能用。从翻译模型走到 GPT，中间还隔着好几篇论文。



A两个原因：能并行、结构通用


论文本身只做了翻译。它的影响来自两点：一是能并行，同样的时间里可以喂进多得多的数据、用上多得多的算力；二是结构通用，拆开一半也能用。


    
  
  • 只用编码器：BERT（2018），擅长理解类任务。
    • 
  
  • 只用解码器：GPT（2018）、GPT-2（2019）、GPT-3（2020，1750 亿参数）。今天的大语言模型基本都是这一路。
    • 
  
  • 把图片切成小块当成“词”：ViT（2020），把 Transformer 带进了计算机视觉。
    • 



B从论文的解码器到 GPT


“自回归”（一个词一个词生成，每次把已生成的词接回输入）不是后来才加的。论文 §3 就写明解码器是 auto-regressive 的，第 8 节演示的遮罩和逐词生成就是它。这个思路本身还要更早：Bengio 2003 年的神经语言模型、Graves 2013 年用 RNN 生成序列、Sutskever 2014 年的 seq2seq 都是逐词预测，这篇论文的贡献是把自回归解码器从 RNN 换成了注意力。


论文没有做的，是把这个解码器单独拿出来当通用模型用。对比一下两种用法：



# 2017 论文：条件生成，必须先有一句原文
enc = encoder(src_tokens)                  # 读英文原句，只算一次
y = ["<s>"]
while y[-1] != "<EOS>":
    y.append(pick(decoder(y, enc)))        # 每一步都通过交叉注意力回头看 enc

# GPT：去掉编码器，没有“原文”，只有前文
y = prompt_tokens                          # 提示词本身就是前文
while y[-1] != "<EOS>":
    y.append(pick(decoder(y)))             # 每层只剩遮罩自注意力 + FFN，没有交叉注意力



结构上，GPT 的一层就是图 1 右边那一栏去掉中间的交叉注意力。训练目标也跟着变了：论文学的是“给定英文句子，生成德文句子”，要 450 万对人工翻译好的句子；GPT 学的是“给定前文，预测下一个词”，任何文本都能当训练数据，不需要标注。数据量的上限因此一下子打开了。



下面这几篇论文把这条路一步步走通：

分工：这篇论文提供了机制（因果遮罩 + 逐词生成）和结构（注意力 + FFN + 残差的层，可以无限往上叠）。“只用解码器、在海量无标注文本上预测下一个词、把规模做大、再对齐人类意图”这条路线，是上表里的后续论文建立起来的。读 GPT 类论文时，遮罩、多头、FFN 这些都不用再学，看它们改了什么就行。

如果你接下来要读 GPT 类模型的代码，会发现它和论文有几处不同。骨架没变，零件换了：
